surfaces, hairline separators, soft-fill selection, Geist text and JetBrains Mono metadata.

## Shared rules

- **Layout:** one surface per area; no rounded card surrounding the whole sidebar/main.
  Pages use a 960px reading width, responsive 20–48px side padding and 24/32/48px section
  spacing. Settings keeps a section index and one scrollable reading column; its title
  stays visible while scrolling. Small windows use horizontal section tabs.
- **Type:** 14px body, 26px page headings, 18px dialog headings, 12–13px labels and supporting
  text. Numbers, times, states, shortcuts and paths use the theme's mono font.
- **Selection:** neutral soft fill, without an accent border, glow or tinted badge. Colour
  remains useful for provider marks, state, errors, diffs and deliberate theme colours.
  Theme previews, user-selected message colours and optional community-theme treatments
  are preserved.
- **Controls:** shared button/input rhythm; custom, theme-aware listboxes in the theme
  editor and gallery; custom checkboxes/toggles; linked settings tabs with arrow/Home/End
  navigation. Keyboard focus remains visible.
- **Motion:** 180ms, eased, without overshoot. Views, tabs and popovers enter gently;
  programmatic pane geometry changes interpolate, while pointer resizing stays immediate.
  The composer no longer has an orbiting accent glow. Both OS reduced motion and the app's
  Reduced/Off settings disable animations, transitions and smooth scrolling.
- **Scrolling:** thin themed scrollbars, contained scrolling and stable page gutters;
  only the sidebar project list scrolls above its pinned footer.

## Screen audit

| Area | Result |
| --- | --- |
| Window/title/top bar | Blended chrome, plain mono counts, flat view controls |
| Sidebar | Brand header, hover shortcuts, provider marks on chat/Usage, project counts and empty states, icon rail with working pulse, flat account footer and version/count line |
| Grid/chat/terminal | Flat focused header, one separator between panes, smooth layout changes, quiet composer and theme-owned message colour |
| Projects | Reading width, spacious text rows, shared title/search/delete controls |
| Usage | Unboxed limit windows, thin meters, mono numbers/reset times, provider avatar styles scoped to avoid inherited pills |
| Accounts | Reading width, airy rows, shared actions and badges; folders/drag/drop retained |
| Settings/theme tools | Shared content rhythm across all sections, sticky title, keyboard tabs and custom listboxes |
| Mods/Changes | Same content width/controls; flat diff sections, status colours retained |
| Dialogs/menus/palette | One popover surface, consistent spacing/type and entrance; soft-fill selected rows |

**Scheduled** remains the functional scheduler tracked by #77. This styling pass does not
add a nonfunctional Scheduled page, job count, or send-later action.

## Verification and regeneration

`tests/e2e/ui-design.spec.ts` exercises all five built-in themes and a user-supplied theme,
page overflow, sidebar identity/rail/footer, custom listbox selection and keyboard controls,
settings tab navigation, and reduced motion. Existing e2e coverage checks pane layout and
resizing, the responsive drawer, theme editing, accounts, Usage and chat behavior.

After `bun run build`, set `WRAITHGRID_UI_SHOTS=<directory>` when running that spec to save
chat, Project, Usage, Accounts, Mods, Settings, dialog, palette, menu and terminal previews
for every theme. Run the existing responsive/theme/editor suites alongside it.
